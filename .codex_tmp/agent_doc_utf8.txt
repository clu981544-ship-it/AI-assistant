[1] AI Chat Assistant、AI衣搭助手、Personal Career Agent 项目总结与推进规划
[2] 定位结论：这三个项目不应被看作三个孤立 Demo，而应组合成一条清晰的 AI 应用工程成长线：先证明 LLM API 与后端工程能力，再证明垂直场景产品化能力，最后用 RAG / Agent 做个人能力证据系统，直接服务实习投递与面试验证。
[3] 一、三个项目总览
[4] 二、项目一：AI Chat Assistant
[5] 核心价值
[6] 它是 AI 应用工程的基础盘，能证明你不是只懂 Prompt，而是能把模型能力接入到可交互产品中。
[7] 它适合作为后续 RAG、Agent、工具调用、部署和工程化能力的母体项目。
[8] 它与 AI 应用工程师实习 JD 中常见的 Python、API、LLM、数据库、前后端通信能力直接相关。
[9] 最该补强
[10] SSE 或 WebSocket 流式输出，让模型回答逐步返回。
[11] 模型 Provider 封装，兼容 DeepSeek、OpenAI、Qwen 等 OpenAI 风格接口。
[12] 日志、超时、重试、异常兜底和请求 ID，体现工程稳定性。
[13] Docker 一键启动、README 架构图、接口说明和运行截图。
[14] 简历表达
[15] 基于 FastAPI + OpenAI SDK + SQLite 构建支持多会话、多轮上下文和历史恢复的 AI Chat Assistant Web 应用；封装 DeepSeek API 调用层，设计最近 10 条消息上下文截断策略，并实现聊天记录持久化、会话隔离、异常提示和基础前端交互。
[16] 三、项目二：AI衣搭助手
[17] 核心价值
[18] 它不是普通聊天机器人，而是有结构化衣物数据、约束条件、推荐逻辑和反馈闭环的垂直 AI 应用。
[19] 它能展示产品理解：用户为什么需要、核心流程是什么、哪些反馈会影响下一次推荐。
[20] 它能展示工程取舍：MVP 阶段用本地 JSON 和图片目录验证闭环，后续再迁移数据库和对象存储。
[21] 推荐架构
[22] 用户录入衣物，系统保存类别、颜色、风格、季节、正式程度、保暖等级、图片和穿着记录。
[23] 用户选择场景和天气，系统先用规则筛选可用衣物。
[24] 系统生成候选搭配，再让 LLM 负责排序、解释和输出自然语言理由。
[25] 用户提交喜欢、不喜欢、太冷、太热、太正式、太休闲、已穿等反馈。
[26] 系统把反馈转成偏好权重，逐渐优化后续推荐。
[27] 最该补强
[28] 衣物数据模型要专业，不能只保存名称、图片和描述。
[29] 推荐逻辑要采用“规则筛选 + LLM 排序解释”，不要完全依赖大模型自由发挥。
[30] 用 Zod 约束 AI 输出结构，保证前端能稳定渲染。
[31] 加入反馈权重和近期穿着惩罚，让项目有真实个性化闭环。
[32] 后续可加入多模态图片识别，自动生成衣物类别、颜色、风格和季节标签。
[33] 简历表达
[34] 基于 Next.js App Router 构建前后端一体的 AI 穿搭推荐应用，设计数字衣橱数据模型，结合天气、场景、近期穿着记录和用户偏好生成可解释穿搭建议；使用 Zod 约束模型输出，采用规则筛选与 LLM 排序解释结合的推荐流程，并通过用户反馈持续优化推荐结果。
[35] 四、项目三：Personal Career Agent
[36] 核心价值
[37] 它把简历、项目复盘、实习经历、技术决策和作品链接蒸馏为结构化知识库。
[38] 它通过 RAG 检索和来源引用降低幻觉，让回答有依据。
[39] 它支持 HR 粘贴 JD 后输出强匹配、部分匹配、不匹配能力项和证据来源。
[40] 它能直接放在简历顶部，作为可交互作品集链接。
[41] 最小可行版本
[42] 首页 30 秒摘要：你是谁、目标岗位、核心技能、代表项目和可验证链接。
[43] 项目证据库：每个项目包含目标、职责、技术方案、关键取舍、困难、复盘和链接。
[44] 带来源引用的问答：回答必须显示依据，无法从资料判断时明确说不确定。
[45] JD 匹配报告：识别岗位方向、匹配经验、能力缺口和建议面试问题。
[46] Agent 化升级
[47] retrieveProfileEvidence：检索个人经历证据。
[48] analyzeJD：解析岗位职责、技能要求和隐性能力要求。
[49] matchJDWithProfile：把 JD 要求与个人证据库逐项匹配。
[50] generateInterviewQuestions：基于岗位和项目生成面试官最可能问的问题。
[51] createResumeSummary：生成面向指定 JD 的简历摘要或项目亮点。
[52] 简历表达
[53] 构建面向 HR 和面试官的 Personal Career Agent，基于简历、项目复盘、实习经历、技术决策和作品链接构建结构化知识库；实现 RAG 问答、来源引用、无依据拒答和 JD 匹配分析，自动输出强匹配、部分匹配、不匹配能力项及对应证据，并生成建议面试问题。
[55] 五、三个项目如何组合成求职主线
[56] 推荐主线：AI Chat Assistant 证明基础工程能力，AI衣搭助手证明垂直产品化能力，Personal Career Agent 证明 RAG / Agent / 岗位匹配能力。三者不要平均用力，应按求职转化价值排序。
[57] 六、30 天推进路线
[58] 第 1 周：整理个人知识库，把简历、AI Chat Assistant、机器人实习和项目复盘拆成 Markdown 文档。
[59] 第 2 周：完成 Personal Career Agent 的基础 RAG，支持文档分块、Embedding、Top-K 检索、上下文拼接和来源引用。
[60] 第 3 周：完成 JD 匹配模块，输出强匹配、部分匹配、不匹配、证据来源和建议面试问题。
[61] 第 4 周：工程化收尾，加入 Zod 校验、异常处理、日志、README、架构图、Demo 截图和部署说明。
[62] 七、简历与面试使用方式
[63] 简历顶部放 Personal Career Agent 链接，描述为：可交互个人能力档案，支持项目问答和 JD 匹配。
[64] AI Chat Assistant 用来回答 LLM API、上下文管理、数据库和后端工程问题。
[65] AI衣搭助手用来回答 AI 产品闭环、个性化推荐、结构化输出和用户反馈问题。
[66] Personal Career Agent 用来回答 RAG、检索增强、来源引用、无依据拒答、工具调用和岗位匹配问题。
[67] 八、现在就可以执行的行动清单
[68] 先做 Personal Career Agent，作为未来 30 天主项目。
[69] 把 AI Chat Assistant 和机器人实习经历整理成结构化项目文档。
[70] 完成 RAG 问答和来源引用，不要只做上传 PDF 聊天。
[71] 加入 JD 匹配报告，让项目直接服务求职。
[72] 再回头工程化 AI Chat Assistant，并把 AI衣搭助手作为第二阶段垂直 AI 产品项目。
